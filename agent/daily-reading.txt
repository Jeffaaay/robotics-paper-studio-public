每天上午9点，按 America/Los_Angeles 的日期，在独立新任务中推进这个阅读与内容项目。每天的推荐不再追加到旧综合聊天。

先看 AGENTS.md、config.json、context/START_HERE.md。运行 python tools/reading_context.py，再读 context/READING_INDEX.md 和当天已有日志。需要去重时查询 context/reading-index.json 的 ID/URL；需要具体进度时只打开相关论文的 PROGRESS 与日志。不要通读旧聊天或全部历史笔记。当前任务用户的新偏好优先，并及时保存供下一独立任务使用。先确认本地工作及 GitHub 私有仓库状态；不覆盖未提交工作，不强行重置或解决未知冲突。

推荐：每天选出3篇候选，让用户自己选1篇。1篇首选、2篇真正不同的备选。优先结合AMR控制/时序/恢复，或OpenArm双臂夹爪叠衣/数据采集/模仿学习。先查已有候选和已读记录，避免重复；若有未完成的阅读，给“继续这一篇”的选项，不把未完成自动记作已读。期刊论文优先，但相关高水平会议、经典方法可以推荐；较新的报告明确标注未核实同行评审。不要为追求新而堆热点。

每个候选必须有：准确题目、作者、年份、期刊/会议与同行评审状态、原论文链接、项目/代码链接如实际存在、为什么适合用户、一个可以动画解释的问题、开始阅读的位置、估计阅读负担、来源核查时间、是否曾讨论。核实原始论文/作者/出版机构，不只看搜索摘要。推荐阶段未精读的方法/结果要注明还需核对；不能写成已完成的论文分析。

把候选保存到当天 journal/YYYY-MM-DD.json，用 tools/journal.py create 保证重跑不覆盖。该工具会同时生成便于阅读的 journal/YYYY-MM-DD.md、阅读日历 journal/README.md，并更新仓库首页入口；这些页面一起提交。直接修改JSON后运行 tools/reading_view.py 刷新。给用户的链接必须指向渲染好的Markdown阅读卡，不再让用户阅读JSON。如果当天已有卡片，继续已有记录，不另建相同候选或同日提醒。向用户发送简短中文推荐，候选标题和对外内容可用英文，并让用户回编号/题名。这个每日推荐是用户要求的通知。必要时只附一句未完成项，不反复催促同一个未变化问题。

用户选定后：记录真实选择，先查 papers/registry.json。有该篇任务时给出原任务入口，不新建重复任务；没有时，按已获授权创建一个干净的单篇任务，遵循 agent/paper-reading.txt 并登记返回的实际 ID。把用户当前问题和笔记随短交接传过去，避免让用户重复输入；不复制全部历史。精读、用户笔记、成片与审核在该篇任务继续。未选中的候选不建任务。接收用户原话，允许中文、英文和语音转写；提供解释时另存 assistant_notes。读完必须有用户确认；完成精读和复现是不同状态。

笔记齐备后：读相关原文、查准确的章节/公式/图表和必要条件，提炼一个用户实际关心的点，写英文storyboard和caption，然后使用现有Manim制作流程或合适的代码动画完成可播放视频。必要时做少标签/无标签两个版本。不要预先替用户选论文并制造心得。用实际用户观点拟一条X草稿：观察→证据→个人判断/疑问→来源；用户没表达观点时先问，不代写一个虚假的第一人称结论。

交付前：检查媒体尺寸、时长、全部场景/转场及文字；把视频和帖文加入本地审核队列，标明原文证据、教学示意和未复现状态。所有公开发布仍由用户逐条审看和明确批准；没有批准就保持待审核。禁止自动发布、代按批准、把提醒当作发布、虚构views或连续打卡。

持久化：每天的推荐、真实进度、AI草稿和用户原话笔记在这个私有仓库保存；已有长笔记链接到robotics-research-notes。任何push之前确认仓库仍private，只提交本次范围内文件。可以使用GitHub插件；本机CLI需要Jeffaaay身份时在当前子进程环境设置GH_TOKEN=gh auth token --user Jeffaaay，不打印token，不改变全局活跃账号。同步失败就保留本地文件并报告，不假称GitHub已更新。
